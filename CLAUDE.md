# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A prototype build of **DGT** (Digital Governance Transmigration — formerly branded "SVKE" / Sistem Visualisasi Keputusan Eksekutif, still the name in some historical commit messages and `DGT.md`'s own spec text) for Indonesia's transmigration-area (kawasan transmigrasi) leadership, plus a companion CRUD tool for its master data. The original tools (now under `legacy-static/`, plus `gis-dgt/` still at repo root) have no build system, package manager, or test suite — everything there is static, dependency-free HTML/CSS/vanilla JS, one self-contained `index.html` per tool. `angular-app/` (see below) is the one exception: a real Angular 8 + TypeScript + Bootstrap 4 workspace with its own `package.json`/`angular.json` — added as a from-scratch reimplementation for a team standardized on that stack, and **now the thing actually served at the live root URL** (see "Hosting / visibility"), built by CI since this repo itself still has no build step for it.

## Common commands

There is nothing to install or build. To preview a tool, just open its `index.html` in a browser (the root launcher's relative links between folders only resolve over `http(s)://`, e.g. via GitHub Pages or a local static server — opening the root `index.html` directly as `file://` still works for the links themselves, since browsers follow relative `file://` paths too).

To save and publish a change:

```bash
git add -A
git commit -m "..."
git push
```

Commits should be small and describe the user-visible change (e.g. "Add schematic map view to Geospasial module"), since the main reason this repo exists is to make it easy to look back at `git log` or revert (`git revert`/`git checkout <hash> -- dashboard/index.html`) to a prior working state.

## Hosting / visibility

The GitHub repo is `amislaha/dgt-dashboard`. Timeline: **public** through 2026-08-26 → switched to **private** on request (prompted by real-looking government-emblem assets landing in `design-system/`, see above), which auto-disabled GitHub Pages → switched **back to public on 2026-08-28** on request (user explicitly okayed the unverified-provenance emblem, now wired into every page's topbar since commit `8f8c3fe`, being publicly visible), and Pages re-enabled from `master` branch root.

So right now: the live site is **https://amislaha.github.io/dgt-dashboard/**. Pages config itself is unchanged from the above (`build_type: legacy`, source `master` branch, path `/` — verify with `gh api repos/amislaha/dgt-dashboard/pages`) — it still just serves whatever's physically sitting in the `master` branch root, no Pages settings were touched for the change below. GitHub Pages requires the source repo to be public unless the account is on a paid plan (GitHub Pro/Team/Enterprise) — this repo relies on being public. If it's ever made private again, Pages auto-disables and the URL 404s until it's flipped back (`gh repo edit amislaha/dgt-dashboard --visibility public --accept-visibility-change-consequences`, then re-POST `repos/amislaha/dgt-dashboard/pages` with `source[branch]=master` `source[path]=/`).

**What's served at the root URL changed** (on request, so the Angular team's port would actually be the live thing, not just source sitting in the repo): `index.html`, root `assets/`, `dashboard/`, and `data-manager/` were moved to `legacy-static/` (still in the repo, still browsable via `file://` or a local static server, just no longer what Pages serves at those paths) to free up the root URL space for the Angular build. **`geomapping/` joined them later**, once its own Angular port (`angular-app/src/app/geomapping/`) needed the `/geomapping` path too — same reasoning, same move, done after the port was found to be unreachable at its intended URL (GitHub Pages serves a real file at an exact path before ever falling through to the SPA, so the old static `geomapping/index.html` was silently winning over the Angular route until it moved). `.github/workflows/deploy-angular.yml` builds `angular-app/` (Node 12, `ng build --base-href /dgt-dashboard/`) on every push that touches `angular-app/**`, then **commits the compiled output (`index.html` + hashed JS/CSS bundles + a `404.html` copy of `index.html`, the standard GitHub-Pages SPA-routing fallback since Pages can't do server-side rewrites) directly back into the `master` root** via a bot commit (`git add` scoped to exclude `legacy-static/`, `gis-dgt/`, `design-system/`, `angular-app/`, `DGT.md`, `CLAUDE.md`, `.github/` — see the workflow file's own comments). This is a deliberate anti-pattern (build output living in source control) chosen specifically to avoid switching Pages to Actions-native deployment, which would mean Pages serves *only* what that workflow uploads and would silently 404 `gis-dgt/`/`design-system/`/`legacy-static/` — all of which are still reached today by Pages serving the whole branch as static files. **`gis-dgt/` and `design-system/` are untouched and still reachable at their existing paths** exactly as before; the root URL itself, `/dashboard/`, `/data-manager/`, and (as of the geomapping port) `/geomapping/` now resolve to the Angular SPA instead of the old static files — the old static tools are still there, just under `legacy-static/` (`legacy-static/dashboard/`, `legacy-static/data-manager/`, `legacy-static/geomapping/`). First deploy happens on the next push to `master` under `angular-app/**` — check `gh run list --workflow=deploy-angular.yml` for status; if `npm install`/`ng build` fails in CI (a real risk — see `angular-app/README.md`'s Node-version caveat, now empirically testable via that workflow's logs rather than just theorized), the root URL keeps serving whatever the last successful bot commit produced (or, before the first successful run, will 404 on `/` until one succeeds, since `legacy-static/index.html` is no longer at the path Pages looks at).

## Architecture of dashboard/index.html

Everything lives in one file: inline `<style>`, inline `<script>`. The only external requests are the Leaflet CDN (`<link>`/`<script>` in `<head>`) and OpenStreetMap tiles used by the real basemap — everything else, including all imagery, is self-contained. This matters if the file is ever hosted as a Claude Artifact, which has a strict CSP blocking any external CDN/tile request: the live basemap degrades gracefully there (see below), but only actually works on GitHub Pages.

**Data layer** — near the top of the `<script>`: plain JS arrays/objects (`kawasan`, `provinces`, `ewsAlerts`, `sCurve`, `komoditas`, `infraKategori`, `klCollab`, `asalDaerah`, `nationalKPI`). All values are fabricated/illustrative, not real ministry statistics — the UI no longer says so on-screen (the "Data ilustratif" topbar note and the per-page footnote repeating it were both removed on request), so this fact now lives only here and in git history. Don't treat kawasan names, coordinates, or figures as authoritative; when adding data, keep it clearly fictional and internally consistent (`lat`/`lon` are real-world approximate coordinates used by the actual basemap; `mapX`/`mapY` are unused leftovers from a removed locator inset — ignore them, don't build new features on them).

**Chart layer** — hand-rolled SVG chart builders (`barChart`, `lineChartDual`, `donut`, `gauge`), each a plain function that takes data + an `opts` object and returns an `<svg>` element via the `el()` namespaced-element helper. No charting library. `gauge()` draws its value arc as a half-circle sweep (0–180°), so its SVG arc's large-arc-flag must always be `0` — the value angle can never exceed 180°, so it's never the "major" arc; a `frac > 0.5` style ternary there is a recurring bug (it was wrong once already), not a legitimate threshold.

**Routing / state** — a single global `state` object (current tab, selected kawasan/province, filters, sort, toggles; `state.tab` defaults to `"geospasial"`) and a `MODULES` array (id, label, sub-label) drives the left sidebar — `MODULES` lists Geospasial first since it's the landing module, not in the "01/02/03…" order the individual `renderX()` functions' own comments still use (those comment numbers are stale/cosmetic, harmless — don't renumber them just to match `MODULES` order). Each module has a `renderX()` function (`renderProfil`, `renderGeospasial`, `renderDemografi`, `renderInfrastruktur`, `renderMonitoring`, `renderEkonomi`, `renderAnalitik`, `renderIntelijen`) registered in the `RENDERERS` map. `render()` clears `#main` and mounts the current tab's function output — every module, including Geospasial, renders into `#main`'s normal padded box now (`render()` no longer toggles a `.no-pad` class; that was specific to Geospasial's earlier full-bleed layout, since removed — see below). Each `renderX()` builds its markup as an HTML template string via the `h()` helper (wraps a string in a detached `<div>`), then wires up event listeners with the `qs`/`qsa` query helpers scoped to that `wrap` element — there's no reactive framework, so any state change that should update the DOM calls a local re-render function explicitly (e.g. `renderProvGrid()`, `renderDetail()`, `renderEWS()`). The left module-nav rail itself (`#rail`, distinct from anything inside Geospasial) fully collapses on desktop via a topbar button, `#railCollapseToggle` (`.rail.collapsed` → `width:0;padding:0;border-right:none;overflow:hidden`, handing that space back to `.main`) — not an icon-only mini-rail, it disappears completely, which is why the toggle button lives in the topbar rather than inside `.rail` itself (a button inside a 0-width container would vanish along with it). This is a separate mechanism from the pre-existing mobile off-canvas `.rail.open`/`#railToggle` behavior for ≤760px, which is untouched; `checkWidth()` shows exactly one of the two toggle buttons at a time (`#railToggle` narrow, `#railCollapseToggle` wide) so there's never a redundant pair in the topbar.

**Sidebar icons** — `ICON_PATHS`/`railIcon()` hold hand-drawn 24×24 line-icon SVG path data keyed by module id, rendered via `currentColor` so they pick up the active/inactive rail color from CSS. `miniIconSvg()` reuses two of those same paths for the Geospasial style-switch buttons.

**Geospasial module layout** — `state.tab` defaults to `"geospasial"`: it's the landing view. **Rebuilt a second time** (on request, from a wireframe labeled "Executive DSS Dashboard") as a normal boxed light-panel page — the earlier immersive full-bleed map with a dark glassmorphism HUD sidebar (described in older commit messages/history) was torn out entirely: no more `.geo-immersive`, `.main.no-pad`, or any `.hud`/`.hud-sidebar*` CSS (that whole ~180-line block is gone). `renderGeospasial()` now returns the same shape every other module does — `pageHead()` + stacked `.panel`s inside `.main`'s normal padding — so it reads consistently with Profil/Demografi/etc. rather than as a special case.

Structure top to bottom: a `pageHead()` toolbar holds the DSS control row — `<span class="info-chip">` for "Site" and "Periode" (static text; there's no per-site or per-period field in the illustrative dataset, so these are deliberately non-functional context chips rather than dropdowns that would silently do nothing) and a real `#geoAreaSelect` ("Area", backed by the `provinces` array, drives `state.geoArea` and re-filters the Summary panel below), plus an `.alert-chip` (`#geoAlertChip`) showing the live unacknowledged-EWS count that smooth-scrolls to the EWS panel on click. Below that, `.stg-strip-row` is the national executive-summary strip (unchanged in *purpose* from before — one metric per other module, per the original request "geospasial jadi dashboard utama... biar gak usah ke menu lain" so an executive never has to leave this screen — Kawasan Mandiri/Populasi/Indeks 5T/Realisasi Anggaran/Capaian Infrastruktur/Komoditas Unggulan/Peringatan Aktif), but restyled as light `.stg-tile`s in a horizontally scroll-snapped `.stg-strip` with `‹`/`›` nav buttons (`#geoStgPrev`/`#geoStgNext`, plain `scrollBy()`) and an up/down trend arrow per tile (`stgTile()` helper; deltas are illustrative, matching the ones already shown for the same metrics elsewhere) — the "Peringatan Aktif" tile's arrow flips to red/down when alerts are active, kept in sync with the alert chip and the EWS panel's ack toggle.

The rest is a `.grid-2` (same 1.3fr/1fr responsive two-column class every module's `grid-2` panels use). **Left column**: the map panel (`.panel.geo-map-panel`, `#geoMapPanel`) has a `.panel-header` toolbar of icon buttons — two `.map-tool-btn[data-view]` (dasar/grid, replacing the old `.hud-radio` list, same `state.geoView` toggle and `renderDasar()`/`renderProvGrid()` functions underneath, effectively unchanged internally) — a search toggle (`#geoSearchToggle` reveals `#geoSearchRow`; `doSearch()` does a substring match on kawasan name/provinsi and calls `selectKawasan()`), and an expand toggle (`#geoExpandToggle` adds `.expanded` to grow `#sebaranBody` from 420px to 640px, re-invalidating the Leaflet map size after the transition). `#sebaranBody` itself now sits in a bounded box, not full-bleed — `.geo-map-panel #sebaranBody { position:relative; z-index:1; height:420px }` is what establishes the stacking context that keeps Leaflet's internal panes (z-index up to 700) contained, the same concern the old full-bleed version had, just solved at the smaller panel level instead of the whole viewport. The small "you are here" **locator inset is back** (`.map-locator`/`#geoLocator`, bottom-right of the map panel, hidden in grid view) — it was removed in an earlier pass along with a schematic map view; only the locator was reintroduced here (the schematic "Peta Skematik" view stays gone), reusing the exact same `BASEMAP_STATIC_SRC` image and `basemapPct()` projection math as the offline map fallback, with `renderLocatorDot()` moving one highlight dot to match `state.selectedKawasan`. Below the map, "Detail Kawasan" is now a **tabbed** panel (`#geoDetailTabs`: Profil/Tabel/Grafik/Foto icon buttons, `state.geoDetailTab` persisted in the global `state` object) instead of one fixed-content sidebar section — `renderDetail()` branches per tab: Profil is the old populasi/indeks/legalitas/risiko rows (now `.detail-row`/`.detail-title`/`.detail-legal-label`, light-themed equivalents of the removed dark `.hud-detail-row` etc.), Tabel is a sortable-by-indeks5t table of every kawasan (row click selects), Grafik is a `barChart()` of indeks5t across all kawasan with the selected one highlighted in `--primary`, and Foto is the single photo/`cityIllustration()` fallback moved out of what used to be an always-visible photo strip. There's no more standalone "Daftar Kawasan" list (`renderKawasanList()`/`#kawasanList` are gone) — picking a kawasan now happens via map pin, a Tabel row, or a Summary-panel row, all funneling through the same `selectKawasan()` as before.

**Right column**: four stacked `.panel`s — "Kawasan Teratas & Terendah" (`renderSummary()`, new: ranks by indeks5t, respects the `state.geoArea` filter, splits into top-3/bottom-3 or one plain ranked list when the filtered pool is 6 or fewer to avoid the two lists overlapping); "Peringatan Dini (EWS)" (`renderEwsHud()` → `#ewsHudList`, same `ewsAlerts` data + ack-toggle duplication with Analitik's `renderEWS()` as always — still a deliberate, flagged duplication, not an oversight, per `DGT.md`'s EWS-and-scoring-together premise — just restyled onto the plain light `.ews-item` classes now that there's no dark HUD context to override for); "Komoditas Unggulan" (`renderKomoditasPanel()`, new, a `barChart()` of the same `komoditas` array the Ekonomi module uses); and "Asisten AI" — no longer a floating FAB + popup (`#geoChatFab`/`#geoChatPanel` are gone), now an always-visible embedded panel (`#geoChatLog`/`#geoChatInput`/`#geoChatSend` plus `.chat-suggest` quick-question buttons, matching the Intelijen panel's markup) that calls the same shared `aiAnswer(q)` as before, with its own `chatLog` so the two conversations still don't share history. Finally, `.ticker-bar`/`#geoTicker` is a new running-text marquee (`renderTicker()`, pure CSS `@keyframes tickerScroll`, disabled under `prefers-reduced-motion`) listing unacknowledged EWS alerts or an all-clear message.

`activeLeafletMap` still holds the live map instance for disposal on view-toggle/tab-switch, `STAGE_COLOR_HEX` is still used for marker fills for the same raw-SVG-attribute reason as before, and `renderDasarStatic()`'s CSP fallback is untouched — none of that changed, only the chrome around it.

**Static basemap fallback** — `BASEMAP_STATIC_SRC` is a real OpenStreetMap tile mosaic (zoom 5, Indonesia bounding box), fetched once and baked in as a base64 JPEG data URI (~90KB of text in the `<script>`), so `renderDasarStatic()` can show actual coastlines even where live tile requests are blocked (the Claude Artifact preview). `mercatorPx()`/`basemapPct()` reproduce the exact Web Mercator projection math used when the image was built (see `BASEMAP_BBOX`, matching the crop) to place each kawasan's pin at the correct `%` position over the flat image — if you ever regenerate this image at a different zoom or bounding box, `BASEMAP_BBOX` must be updated to match or every pin will be off. There's no pan/zoom on this fallback and it's explicitly captioned as a static snapshot. It carries the required "© OpenStreetMap contributors" attribution baked into the overlay — keep that visible if this image is ever replaced.

**Area imagery** — the Geospasial "Foto-foto" gallery (`renderGallery()`) shows each `kawasan`'s real photo via its `foto` field (a relative path into `assets/kawasan/`, see below). `cityIllustration(k, w, h)` — an inline SVG skyline (gradient sky + silhouetted buildings + lit windows), seeded deterministically from `k.id` via `seededRandom()` — is the fallback rendered instead whenever a `kawasan` entry has no `foto`, so the gallery still has something to show for future entries added before a real photo exists. This illustration deliberately replaced an earlier version that pulled random stock photos (`picsum.photos`): a random photo service can't be trusted to stay thematically on-brief (a snowy scene turned up for a tropical kawasan) or, more importantly, to avoid depicting real identifiable people in a fabricated government-dashboard context — that risk doesn't apply to the curated photos now in `assets/kawasan/`. There is no separate "photo card" in the Profil drawer or the map info panels; imagery lives only in the gallery panel.

**`assets/kawasan/`** — one subfolder per `kawasan` (folder name = slug of `k.nama`, see the folder's own `README.md` for the id↔folder mapping), holding that area's real photo referenced by relative path rather than baked in as base64. This is an intentional exception to the single-file/self-contained rule above: files here won't load if `index.html` is ever previewed as a Claude Artifact (CSP blocks the relative fetch), only on GitHub Pages or opened directly as `file://`. When adding a new `kawasan`, add a same-slug subfolder with its photo and set that entry's `foto` field — until then it'll fall back to `cityIllustration()`.

**Theming** — deliberately single-theme (light "green/mint" palette defined as CSS custom properties in `:root`), not adapted for dark mode. This was originally a dark "command-center" palette (per the source spec's LED-video-wall / war-room framing) but was switched to light; don't add a dark theme without checking that's actually wanted. As of the "DGT Transmigrasi 2026" Figma design-system sync, the `:root` values (and Plus Jakarta Sans / JetBrains Mono, loaded from Google Fonts — the same CDN-dependency exception as Leaflet) are meant to track that Figma file's Colour/Type/Surfaces pages; re-pull from there rather than re-deriving values ad hoc. `--primary` is the one accent color threaded through most interactive states (was named `--gold` before the sync, when it held an unrelated green — the name is accurate now, so keep it in sync rather than reintroducing a mismatch). `--series-2` doubles as the "info" semantic and chart-series-2 color. The Geospasial module used to be a deliberate, scoped exception to "single light theme" (a dark glassmorphism HUD over a full-bleed map) — that HUD was torn out in a later rebuild (see below) and Geospasial is now single-light-theme consistent with every other module, so this repo currently has no dark-themed surface anywhere. Don't add one without checking that's actually wanted.

**AI Assistant** — a keyword-matching mock, `aiAnswer(q)` (a shared top-level function, not real LLM call), only answers a fixed set of intents (mandiri, risiko, anggaran, indeks/5T) by reading the same in-page data arrays. Two separate chat UIs call it: the Intelijen module's panel (`renderIntelijen`) and the embedded "Asisten AI" panel on the Geospasial dashboard (`#geoChatLog`/`#geoChatInput`/`#geoChatSend` — no longer a floating FAB+popup, that was removed when Geospasial's layout was rebuilt, see below) — each keeps its own `chatLog` array/DOM, so the two conversations don't share history, but both get identical answers to the same question since they call the same function. If the mock's intents ever grow, update `aiAnswer` once rather than each caller.
